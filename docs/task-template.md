# 任务约定模板

这是手工使用的模板，尚非程序输入协议。每个真实任务单独复制填写，勿将密钥或其他敏感信息放入任务记录。

## 基本信息

- 任务 ID：
- 任务约定版本：
- 目标及使用场景：
- 仓库位置：
- 基线 ref 或显式 SHA（ref 首次派发时固定，不自动 fetch）：
- 目标分支及本地交付位置：
- 负责人：

## 队列与调度

- 前置任务及其交付条件：
- 需要使用的前置产物与版本：
- 优先级或排队顺序：
- 必需能力（工具、运行时、网络与仓库访问）：
- 允许或指定的执行后端、运行环境及模型：
- 后端选择偏好（成本、速度等软性条件）：
- 是否允许切换后端及所需确认：
- 允许执行的时段及时区：
- 是否允许等待低价时段：
- 紧急任务的时段例外：
- 任务移出或取消后，对后续依赖的处理：

## 范围与权限

- 需要完成的内容：
- 允许修改的内容：
- 禁止修改的内容：
- 可以执行的验证命令：
- 允许的交付动作（本地修改、提交、推送、创建 MR/PR、合并等分别说明）：
- 需要重新确认的条件：

## 执行记录

每次开始或恢复执行时追加一条，保留原记录。

- 执行尝试 ID：
- 任务约定版本：
- 开始与结束时间：
- 工作区与起始提交：
- 实际执行后端、模型、机器或环境及外部执行标识：
- 产物传递位置与访问方式：
- 结束提交与工作区状态：
- 执行动作及结果：
- 失败或等待原因：
- 恢复前需要重新检查的内容：

## 独立 AI 评审

- 评审端及独立会话标识：
- 评审输入（任务约定版本、代码版本、变更与验证证据）：
- 评审结论与具体意见：
- 测试失败与评审退回共享的修复次数及上限（默认两轮）：
- 需要人工介入的条件：
