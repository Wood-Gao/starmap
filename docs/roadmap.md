## 1. 队列与调度核心

定义统一执行协议、能力声明和结果格式，再实现持久化任务队列，使用可控的模拟实现端和模拟评审端验证调度。模拟评审仅用于验证流程，不能证明真实代码质量。

验收场景：

1. 多任务执行不超过配置的并发上限，完成后自动派发后续任务。
2. 独立任务可以并行；有依赖的任务等待前置交付，并获得指定产物引用。
3. 拒绝循环依赖、自依赖和不存在的任务引用。
4. 插队改变合格任务的派发顺序，不绕过依赖或容量限制。
5. 移出待执行任务后不再派发，其后续任务保持阻塞并显示原因。
6. 失败任务不会堵住无依赖的其他任务；调度过程可追溯。
7. 重启后不丢失任务，重复调度不造成重复占用或重复派发。
8. 配置不同能力的模拟后端，验证任务只派发给符合硬性要求的后端；无匹配时显示阻塞原因。

## 2. 真实实现端与独立 AI 评审

首个实现端采用本地 Codex，全新 Codex 会话独立评审；公司平台和远端 VM 作为后续扩展。同时具备并行所需的工作区隔离与明确的产物集成约定。

验收场景：

1. 真实任务从入队、实现、独立评审走到交付报告。
2. 实现端输出可定位的代码版本及验证证据；评审使用独立会话。
3. 评审不通过后携带意见重新排队修复，达到返工上限时转人工。
4. 代码或任务约定变化后，旧评审结论不会直接作为当前版本的交付依据。
5. 依赖任务获得可用的前置产物；分支冲突有明确处理路径。
6. 接入第二种执行后端，验证通过新增适配器和配置即可复用调度核心；记录实际模型、机器与产物访问方式。
7. 取消或恢复不受支持时，框架明确显示能力限制；切换后端不会造成两个执行同时写入同一工作区。

## 3. 运行恢复与人工控制

完善远端状态核对、异常检测、重试退避、运行中取消及调度事件记录。

验收场景：远端失联或调度器重启后，不重复启动未知状态的工作；取消确认前不释放容量；过期回调不能覆盖当前执行结果或重新激活已取消任务。

## 4. 峰谷策略与持续运行

引入可配置的时区、执行窗口和分时容量策略，明确紧急任务例外。开展长时间运行实验，记录成本、排队时间、吞吐和失败恢复结果。

验收场景：使用可控时钟验证跨窗口调度；运行中任务遵循明确的时段切换策略；持续运行实验有记录和失败分析。成本收益按实际平台计费计算，不预填节省比例。

## 5. 可复现展示

提供安装与部署说明，以及并发与依赖、插队与移出、独立评审返工、失败恢复和分时调度的可复现演示。覆盖调度不变量、状态转换、重复事件及版本绑定的关键测试；根据已实现能力和实测结果编写项目展示材料。
